## 1. 개요

본 문서는 `docs/2-prd.md` FR-01~FR-08 및 `docs/3-user-scenario.md` SC-01~SC-07을 화면 단위로 구체화한 와이어프레임이다. 브레이크포인트는 PRD §5 기준(mobile < 640px, tablet 640~1024px, desktop > 1024px)을 따르며, 목록/등록 화면은 데스크톱과 모바일 레이아웃을 모두 제시한다. 색상/스타일은 텍스트로 설명하며 실제 구현은 CSS media query로 대응한다(PRD §5, 별도 CSS 프레임워크 미도입).

## 2. W-01 로그인 / 회원가입 화면 (FR-01, FR-02)

관련: SC-01, SC-02, BR-01(미인증 접근 허용), BR-02(email unique), BR-09('기본' Category 자동 생성)

하나의 화면에서 "로그인" / "회원가입" 탭으로 전환한다. 진입 시 기본 선택 탭은 로그인이며, URL 쿼리(`?tab=signup` 등)로 회원가입 탭 직접 진입도 가능.

```
┌─────────────────────────────────────────┐
│               TodoList                  │
│                                           │
│   ┌───────────┬───────────┐            │
│   │  로그인 ●  │  회원가입  │            │  ← 탭
│   └───────────┴───────────┘            │
│                                           │
│  이메일                                  │
│  ┌─────────────────────────────────┐   │
│  └─────────────────────────────────┘   │
│                                           │
│  비밀번호                                │
│  ┌─────────────────────────────────┐   │
│  └─────────────────────────────────┘   │
│                                           │
│  [!] 이메일 또는 비밀번호가 올바르지     │  ← 에러 시만 표시
│      않습니다                            │
│                                           │
│         ┌───────────────────┐          │
│         │      로그인          │          │
│         └───────────────────┘          │
└─────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────┐
│               TodoList                  │
│                                           │
│   ┌───────────┬───────────┐            │
│   │  로그인    │ 회원가입 ● │            │  ← 탭
│   └───────────┴───────────┘            │
│                                           │
│  이메일                                  │
│  ┌─────────────────────────────────┐   │
│  │ email@example.com                │   │
│  └─────────────────────────────────┘   │
│  [!] 이미 사용 중인 이메일입니다        │  ← 에러 시만 표시 (BR-02)
│                                           │
│  이름                                    │
│  ┌─────────────────────────────────┐   │
│  │ (1~50자)                         │   │
│  └─────────────────────────────────┘   │
│                                           │
│  비밀번호                                │
│  ┌─────────────────────────────────┐   │
│  │ ●●●●●●●●                        │   │
│  └─────────────────────────────────┘   │
│                                           │
│         ┌───────────────────┐          │
│         │     가입하기        │          │
│         └───────────────────┘          │
└─────────────────────────────────────────┘
```

- 주요 요소: 상단 "로그인 / 회원가입" 탭(라디오 형태, 동시에 하나만 활성화), 이메일/비밀번호 입력(공통), 이름 입력(회원가입 탭 전용), 제출 버튼(탭에 따라 "로그인"/"가입하기" 레이블 전환).
- 탭 전환 시 입력값은 초기화(폼 상태 분리), 에러 메시지도 탭별로 독립 표시.
- 로그인 탭 에러 표시: 이메일/비밀번호 불일치 시 계정 존재 여부 노출 방지를 위해 동일 메시지 사용(SC-02 E1/E3, 401).
- 회원가입 탭 에러 표시: 필드 하단 인라인 에러 텍스트(빨강). 이메일 중복(BR-02)은 "이미 사용 중인 이메일입니다", 필수값/길이 위반(name 1~50자)은 필드별 400 에러 메시지를 인라인 표시(SC-01 E1/E2).
- 회원가입 성공 시 '기본' 카테고리는 서버가 내부 처리로 자동 생성(BR-09) — 별도 안내 없이 동일 email/password로 자동 로그인 후 W-03(할일 목록)으로 바로 이동.
- 로그인 성공 시 access token은 Zustand, refresh token은 HttpOnly 쿠키 저장 후 W-03(할일 목록)로 이동(PRD §5 보안, SC-02).
- access token 만료 시 자동 refresh 흐름은 전 화면 공통 동작(백그라운드 처리, 화면 요소 없음). refresh도 만료 시 이 화면(로그인 탭)으로 강제 리다이렉트되며 상단에 "세션이 만료되어 다시 로그인해주세요" 안내 배너 표시(SC-02 E2).

## 3. W-02 회원정보 수정 화면 (FR-03)

관련: SC-03, BR-06(소유권), BR-07(본인만 가능)

```
┌─────────────────────────────────────────┐
│  ← 뒤로       내 정보                   │
│                                           │
│  이메일 (변경 불가)                      │
│  ┌─────────────────────────────────┐   │
│  │ user@example.com  (readonly)     │   │
│  └─────────────────────────────────┘   │
│                                           │
│  이름                                    │
│  ┌─────────────────────────────────┐   │
│  │ 홍길동                            │   │
│  └─────────────────────────────────┘   │
│  [!] 이름은 1~50자여야 합니다           │  ← 검증 에러 시만 표시
│                                           │
│         ┌───────────────────┐          │
│         │      저장           │          │
│         └───────────────────┘          │
│                                           │
│  ✓ 저장되었습니다                       │  ← 성공 시 토스트
└─────────────────────────────────────────┘
```

- 주요 요소: 이메일(읽기 전용, unique 값이므로 화면상 수정 불가), 이름 입력 필드, 저장 버튼.
- 상태 표시: 저장 성공 시 토스트/인라인 확인 메시지. name 형식 위반(1~50자 초과/미달) 시 400 인라인 에러(SC-03 E2).
- 접근 통제: 본 화면은 `GET/PATCH /api/users/me`만 사용하므로 URL 조작으로 타인 정보에 접근하는 경로 자체가 없음(BR-06/BR-07은 서버 측 토큰 기반 검증으로 보장).
- access token 만료 시 자동 갱신 후 재시도(SC-03 E1), 갱신 실패 시 W-01(로그인 탭)로 리다이렉트.

## 4. W-03 할일 목록/필터링 화면 (FR-06)

관련: SC-05, BR-06(본인 소유만 조회), §5 상태 판정 규칙

### 4.1 데스크톱 레이아웃 (> 1024px)

```
┌───────────────┬───────────────────────────────────────────────────────────────┐

│ ┌───────────┐ │  상태:[전체][시작전][진행중][완료][지연][초기화]                │   목록 스크롤해도 고정

│ │ 기본       │ ├───────────────────────────────────────────────────────────────┤
│ │ 업무       │ │  ┌─────────────────────────────────────────────┐             │

│                │  │                                        [삭제]  │             │
│                │  ├─────────────────────────────────────────────┤             │
│                │  │ [완료]   운동하기 ✓          개인   08/15~08/20│             │
│                │  │                                        [삭제]  │             │
│                │  └─────────────────────────────────────────────┘             │
│ ─────────────  │                                                                 │
│ [🌙 다크모드]   │  카드를 클릭하면 W-04(수정) 진입, 카드 우하단 [삭제]는 W-05 호출│

### 4.2 모바일 레이아웃 (< 640px)

```
┌───────────────────────────┐
│ [전체 카테고리 ▾]          │  ← 드롭다운(사이드바 대체)
├───────────────────────────┤
│ 할일 목록  [카테고리관리][+]│
│ [전체][시작전][진행중]     │  ← 상태 필터 가로 스크롤 chip [초기화]
│ [완료][지연]               │
│ 제목검색 / 시작일~종료일    │
├───────────────────────────┤
│ ┌───────────────────────┐ │
│ │[진행중] 기획서 작성    │ │
│ │ 업무 · 08/20~08/28    │ │
│ │                  [삭제]│ │
│ └───────────────────────┘ │
│ ┌───────────────────────┐ │
│ │[지연]  장보기          │ │
│ │ 기본 · 08/10~08/20    │ │
│ │                  [삭제]│ │
│ └───────────────────────┘ │
│                             │
│ [🌙 다크모드][언어▾][로그아웃]│ ← 사이드바 하단 (세로 스택)
│              ＋ (플로팅버튼)│ ← 새 할일 등록
└───────────────────────────┘
```

- 주요 요소: 카테고리 필터(데스크톱: 좌측 사이드바 목록, 모바일: 드롭다운), 상태 필터(전체/시작전/진행중/완료/지연 — 단일 선택 탭/칩, 선택 여부와 무관하게 뱃지와 동일한 색으로 항상 표시), 필터 초기화 버튼(카테고리/상태/제목검색/날짜범위 중 하나라도 적용된 경우에만 상태필터 우측에 노출), 제목 검색 입력(부분일치), 날짜 범위(from-to) 달력 필터(할일 기간과 겹치는 항목만 표시), Todo 카드(제목/상태 뱃지/카테고리/기간/삭제 버튼 — 카드 클릭 시 수정화면 진입), "카테고리 관리"·"새 할일 등록" 버튼(데스크톱: 우상단 나란히, 모바일: 헤더+플로팅 버튼), 사이드바 하단(다크모드 토글, 언어 선택, 로그아웃 — 모바일에서는 사이드바 안 세로 스택), 사이드바 중간 지점의 장식용 마스코트 아이콘.
- 레이아웃 고정: 데스크톱에서 좌측 사이드바 전체와 상단 툴바(제목/버튼/필터/검색)는 `position: sticky`로 고정되어 카드 목록만 스크롤된다. 배경색은 사이드바(패널색) / 상단 툴바(패널색보다 옅은 톤) / 카드 목록 영역(페이지 배경)이 서로 다르게 구분된다(`docs/9-style.md` §6 다크모드 토큰 참고).
- 상태 뱃지 색상/의미(`docs/9-style.md` §5 값 그대로):
  - 시작전: 회색(`#E4E8F1`/`#5B667A`) — 아직 시작일 이전
  - 진행중: 파랑(`#2F8CFF`) — startDate ≤ 오늘 ≤ endDate
  - 완료: 초록(`#2FBF71`) — isDone=true (체크 아이콘 병기)
  - 지연: 빨강(`#E5484D`) — isDone=false, endDate < 오늘
- 빈 상태: Todo가 없거나 필터 결과 없음(카테고리/상태/제목검색/날짜범위 조합 포함) → 카드 목록 대신 "할일이 없습니다" 안내(SC-05 E1, 에러 아님).
- 필터 결과는 항상 본인 소유 Todo만 표시(BR-06). 카테고리/상태는 서버 쿼리(`GET /api/todos?categoryId=&status=`), 제목검색/날짜범위는 조회된 목록을 클라이언트에서 추가 필터링한다(별도 API 없음).
- 다크모드/언어 선택은 클라이언트 로컬 상태(localStorage)로 유지되며 서버와 무관하다.
- access token 만료 시 목록 로딩 스피너 유지 후 자동 갱신·재조회(SC-05 E2).

│                                                   │
│  ☐ 완료 처리                                     │  ← 수정 화면에서만 노출
│                                                   │
│         ┌───────────────┐                      │
│         │     저장         │                      │
│         └───────────────┘                      │
└───────────────────────────────────────────────┘
```

### 5.2 모바일 레이아웃 (< 640px)

```
┌───────────────────────────┐
│ ← 할일 등록                │
├───────────────────────────┤
│ 제목                        │
│ ┌─────────────────────┐   │
│ └─────────────────────┘   │
│                             │
│ 카테고리                    │
│ ┌─────────────────────┐   │
│ │ 선택 안 함(기본) ▾   │   │
│ └─────────────────────┘   │
│ ※ 미선택 시 '기본' 적용     │
│                             │
│ 시작일                      │
│ ┌─────────────────────┐   │
│ │ 2026-08-20      📅  │   │  ← 탭 시 전체화면 캘린더
│ └─────────────────────┘   │
│ 종료일                      │
│ ┌─────────────────────┐   │
│ │ 2026-08-28      📅  │   │
│ └─────────────────────┘   │
│                             │
│ ☐ 완료 처리 (수정 시)      │
│                             │
│ ┌─────────────────────┐   │
│ │        저장           │   │
│ └─────────────────────┘   │
└───────────────────────────┘
```

- 주요 요소: 제목 입력(1~100자), 카테고리 드롭다운(본인 카테고리 목록 + "선택 안 함(기본 적용)" 옵션), 시작일/종료일 날짜 입력(캘린더 UI, FR-05), 완료 처리 체크박스(수정 화면 전용, 등록 화면에는 없음 — 신규 Todo는 항상 isDone=false), 저장 버튼.
- 카테고리 미지정 안내: 드롭다운 기본값이 "선택 안 함(기본 적용)"이며 하단에 "선택하지 않으면 '기본' 카테고리가 자동 적용됩니다" 안내 문구 상시 노출(BR-03, SC-04 대안 흐름).
- 캘린더 UX: 종료일 캘린더는 시작일 이전 날짜를 비활성화하여 1차 방지(SC-04 E1 서술과 일치), 그래도 우회 입력 시 서버 검증(BR-05) 실패로 "종료일은 시작일 이후여야 합니다" 인라인 에러 표시.
- 에러 표시:
  - startDate > endDate: 인라인 에러(BR-05, SC-04 E1 / SC-06 E3)
  - 존재하지 않거나 타인 소유 categoryId(위변조 등): 저장 실패 토스트 "유효하지 않은 카테고리입니다"(BR-04, SC-04 E2 / SC-06 E4)
  - title 누락/100자 초과: 필드 인라인 에러(SC-04 E3)
  - 수정 화면 진입 시 대상 Todo가 타인 소유면 목록 진입 자체가 불가하므로(BR-06) 이 화면에는 도달하지 않음 — 직접 URL 조작 시 403 처리 후 목록으로 리다이렉트 + "접근 권한이 없습니다" 안내(SC-06 E1)
  - 존재하지 않는 Todo id로 진입 시 404 → "할일을 찾을 수 없습니다" 안내 후 목록 이동(SC-06 E2)
- 등록/수정 성공 시 W-03(목록)로 이동, 변경된 Todo가 반영되고 상태 뱃지 재계산.

## 6. W-05 할일 삭제 확인 다이얼로그 (FR-08)

관련: SC-07, BR-06(소유권)

```
        ┌───────────────────────────────┐
        │        할일을 삭제할까요?       │
        │                                   │
        │   "기획서 작성"                  │
        │   삭제 후에는 되돌릴 수 없습니다.│
        │                                   │
        │   ┌─────────┐   ┌─────────┐   │
        │   │  취소     │   │  삭제     │   │
        │   └─────────┘   └─────────┘   │
        └───────────────────────────────┘
              (모달, 배경 dim 처리)
```

- 주요 요소: 삭제 대상 Todo 제목 표시, "취소"(secondary) / "삭제"(danger, 빨강) 버튼. 모바일/데스크톱 동일 모달 레이아웃(작은 화면에서는 하단 시트로 대체 가능).
- 동작: W-03(목록) 또는 W-04(상세/수정)에서 삭제 버튼 클릭 시 이 다이얼로그 표시(SC-07 기본 흐름 2단계). "삭제" 확정 시 `DELETE /api/todos/:id` 호출.
- 상태/에러 표시:
  - 성공: 다이얼로그 닫힘 + 목록에서 해당 카드 즉시 제거 + "삭제되었습니다" 토스트
  - 타인 소유 Todo id(URL 조작 등): 403 → "삭제 권한이 없습니다" 토스트, 목록 유지(BR-06, SC-07 E1)
  - 이미 삭제된/존재하지 않는 Todo id: 404 → "이미 삭제된 할일입니다" 토스트 후 목록 새로고침(SC-07 E2)
  - access token 만료: 자동 갱신 후 삭제 재시도(SC-07 E3)

## 7. W-06 카테고리 관리 화면 (FR-04)

관련: SC-08, BR-06(소유권), BR-08(기본 삭제 금지), BR-10(기본 이름 변경 금지)

```
┌─────────────────────────────────────────┐
│  ← 할일 목록                             │
│  카테고리 관리                           │
│                                           │
│  ┌───────────────────────┐  ┌────────┐ │
│  │ 새 카테고리 이름        │  │  추가   │ │
│  └───────────────────────┘  └────────┘ │
│                                           │
│  ┌───────────────────────────────────┐ │
│  │ 기본                                │ │  ← '기본'은 수정/삭제 버튼 미노출
│  ├───────────────────────────────────┤ │
│  │ 업무              [수정]  [삭제]    │ │
│  ├───────────────────────────────────┤ │
│  │ 개인              [수정]  [삭제]    │ │
│  └───────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

- 주요 요소: "할일 목록"으로 돌아가는 링크, 새 카테고리 이름 입력(1~30자)+추가 버튼, 카테고리 목록. '기본' 카테고리는 [수정]/[삭제] 버튼이 노출되지 않는다(BR-08, BR-10).
- 수정: [수정] 클릭 시 해당 행이 입력창+[저장]/[취소]로 전환되는 인라인 편집(별도 화면 전환 없음).
- 삭제: [삭제] 클릭 시 네이티브 confirm 다이얼로그로 "소속 할일은 '기본' 카테고리로 이동합니다" 안내 후 확정(별도 커스텀 다이얼로그 미도입, YAGNI).
- 에러 표시: 중복 이름(생성/수정 공통) 시 "이미 사용 중인 카테고리 이름입니다" 인라인 에러, '기본' 이름 변경 시도 시 400 에러 메시지 그대로 표시(SC-08 E1/E2).
- 카테고리 생성/수정/삭제는 목록 화면(W-03)의 카테고리 필터에도 즉시 반영된다.

## 8. 공통 UI 규칙 (상태 뱃지/에러 표시)

| 항목             | 규칙                                                                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상태 뱃지 색상   | 시작전=회색, 진행중=파랑, 완료=초록(체크 아이콘), 지연=빨강 (도메인 정의서 §5)                                                                                              |
| 인라인 필드 에러 | 400 검증 실패(필수값/길이/날짜 순서 등) 시 해당 입력 필드 하단에 빨간 텍스트로 표시                                                                                         |
| 토스트 에러      | 403(소유권 위반), 404(리소스 없음) 등 화면 흐름을 막는 에러는 토스트 + 필요 시 목록으로 리다이렉트                                                                          |
| 인증 만료(401)   | 사용자에게 노출하지 않고 TanStack Query 에러 핸들러가 `/api/auth/refresh` 호출 후 원 요청 재시도(백그라운드), refresh도 실패 시에만 W-01(로그인 탭)로 강제 이동 + 배너 안내 |
| 빈 상태          | 목록에 항목이 없을 때는 에러가 아닌 안내 문구("할일이 없습니다")로 구분 표시                                                                                                |
