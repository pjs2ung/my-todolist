## 1. 배경 및 문제 정의

- REQ-01: 인증된 사용자별로 개인 할일을 관리하는 앱이 부재함.
- REQ-02: 할일에 시작일/종료일 개념이 필요함(단순 마감일 관리를 넘어 기간 관리).

## 2. 용어 정의 (Ubiquitous Language)

| 용어                | 정의                                                                              |
| ------------------- | --------------------------------------------------------------------------------- |
| User (사용자)       | 회원가입 후 로그인하여 앱을 사용하는 주체. 본인 소유의 Todo/회원정보만 관리 가능. |
| Category (카테고리) | Todo를 분류하는 단위. 사용자가 미지정 시 '기본' 카테고리가 자동 적용됨.           |
| Todo (할일)         | 사용자가 등록하는 작업 단위. 시작일자/종료일자, 완료 여부, 카테고리를 가짐.       |
| 상태 (Status)       | Todo의 진행 상태. 시작전 / 진행중 / 완료 / 지연 중 하나로 판정됨(파생 값).        |
| 소유권 (Ownership)  | Todo/회원정보는 생성한 User만 조회·수정·삭제 가능하다는 접근 통제 원칙.           |

## 3. 핵심 엔티티 및 속성

### 3.1 User

| 속성                  | 타입     | 제약                            | 설명                    |
| --------------------- | -------- | ------------------------------- | ----------------------- |
| id                    | string   | PK, 필수                        | 사용자 식별자           |
| email                 | string   | unique, 필수                    | 로그인 계정             |
| password              | string   | 필수, 해시 저장(평문 저장 금지) | 인증용 비밀번호         |
| name                  | string   | 필수, 1~50자                    | 사용자 이름             |
| createdAt / updatedAt | datetime | 필수, 시스템 자동 기록          | 가입일시 / 정보수정일시 |

### 3.2 Category

| 속성   | 타입   | 제약                                | 설명                    |
| ------ | ------ | ----------------------------------- | ----------------------- |
| id     | string | PK, 필수                            | 카테고리 식별자         |
| userId | string | FK(User), 필수                      | 소유 User               |
| name   | string | 필수, 1~30자, (userId, name) unique | 카테고리명 (예: '기본') |

### 3.3 Todo

| 속성                  | 타입     | 제약                                                                     | 설명                |
| --------------------- | -------- | ------------------------------------------------------------------------ | ------------------- |
| id                    | string   | PK, 필수                                                                 | 할일 식별자         |
| userId                | string   | FK(User), 필수                                                           | 소유 User           |
| categoryId            | string   | FK(Category), 필수(미지정 등록 요청 시 서버가 '기본' 카테고리 id로 채움) | 소속 Category       |
| title                 | string   | 필수, 1~100자                                                            | 할일 제목           |

| createdAt / updatedAt | datetime | 필수, 시스템 자동 기록                                                   | 등록일시 / 수정일시 |

## 4. 엔티티 관계

- User 1 : N Category (사용자마다 자신의 카테고리 집합을 가짐)
- User 1 : N Todo (사용자마다 자신의 할일 집합을 가짐)
- Category 1 : N Todo (카테고리 하나에 여러 Todo가 속함, Todo는 반드시 하나의 Category에 속함)
- Category 삭제 정책: 사용자는 '기본' 카테고리를 삭제할 수 없음. '기본'이 아닌 카테고리 삭제 시, 소속 Todo는 모두 '기본' 카테고리로 재배정한다(§6 참조).
- '기본' Category는 회원가입 시 서버가 자동 생성한다(BR-09, §6 참조). 모든 User는 최소 1개의 '기본' Category를 보유한다.

## 5. Todo 상태 및 판정 규칙

Todo 상태는 저장되는 값이 아니라 `startDate`, `endDate`, `isDone`, 오늘 날짜(date, 시각 제외)로 매 조회 시점에 파생 판정한다. `isDone`이 날짜 조건보다 우선 판정된다.

| 상태          | 판정 규칙 (isDone = true 인 경우 항상 "완료")    |
| ------------- | ------------------------------------------------ |
| 완료          | isDone = true                                    |
| 시작전        | isDone = false 이고 오늘 < startDate             |
| 진행중        | isDone = false 이고 startDate <= 오늘 <= endDate |
| 지연(overdue) | isDone = false 이고 endDate < 오늘               |

- 판정 우선순위: 완료 → 시작전 → 진행중 → 지연 (isDone=true면 나머지 조건 평가 불필요).
- 경계값: startDate == 오늘은 "진행중", endDate == 오늘은 "진행중"(지연 아님).

## 6. 비즈니스 규칙 및 제약조건

| ID    | 규칙                                                                                                                                     | 관련 기능(§7)              |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| BR-01 | 회원가입/로그인 화면 자체는 미인증 상태로 접근 가능. 그 외 모든 기능은 로그인(인증) 후에만 사용 가능하며, 미인증 접근 시 401로 거부한다. | FR-01, FR-02               |
| BR-02 | 이메일은 시스템 전체에서 unique. 이미 가입된 email로 회원가입 시도 시 거부하고 에러를 반환한다.                                          | FR-01                      |
| BR-03 | Todo 등록 시 Category 미지정이면 서버가 해당 사용자의 '기본' 카테고리를 자동 적용한다.                                                   | FR-04                      |
| BR-04 | Todo의 categoryId가 본인 소유가 아니거나 존재하지 않으면 등록/수정을 거부하고 에러를 반환한다.                                           | FR-04, FR-07               |
| BR-05 | Todo의 startDate <= endDate (시작일은 종료일보다 늦을 수 없음). 위반 시 등록/수정을 거부한다.                                            | FR-04, FR-05, FR-07        |
| BR-06 | 소유권 기반 접근제어: User는 자신이 생성한 Todo/Category/회원정보만 조회·수정·삭제 가능. 타인 소유 리소스 접근 시 403으로 거부한다.      | FR-03, FR-06, FR-07, FR-08 |
| BR-07 | 회원정보 수정은 본인만 가능.                                                                                                             | FR-03                      |
| BR-08 | '기본' 카테고리는 삭제할 수 없다. '기본'이 아닌 카테고리 삭제 시 소속 Todo는 '기본' 카테고리로 재배정한다.                               | FR-04                      |
| BR-09 | 회원가입 시 서버는 해당 사용자의 '기본' Category를 자동 생성한다.                                                                        | FR-01                      |
| BR-10 | '기본' 카테고리는 이름을 변경할 수 없다. 자동 적용(BR-03)·삭제 재배정(BR-08) 로직이 이름 '기본'으로 카테고리를 식별하기 때문이다.        | FR-04                      |
